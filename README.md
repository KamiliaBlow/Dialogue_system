# Диалоговая система

Радиоэфир с НПЦ для настольных ролевых игр в научно-фантастическом сеттинге (делалась под Lancer RPG).

Между игровыми сессиями игроки заходят на сайт, «настраивают приёмник» на частоту и слушают переговоры с персонажами мира. В нужный момент им предлагают выбрать ответ, и разговор идёт дальше по выбранной ветке. Мастер видит, кто что выбрал, и использует это в следующих сессиях.

Так игроки знакомятся с будущими НПЦ, поддерживают связь со старыми знакомыми и не скучают, пока игра на паузе.

> Проект в бета-версии: возможности меняются и дорабатываются.

---

## Что видит игрок

- **Терминал связи.** Портреты собеседников, частота, текст печатается «вживую». Если есть озвучка, текст печатается вместе с голосом. На выборе появляются варианты ответа.
- **Досье пилота.** До трёх пилотов на аккаунт: позывной, имя, мех, аватар. Активный пилот — тот, от чьего имени игрок выходит в эфир.
- **Сословие.** Лансер, Кавалер в Доме или Кавалер-изгнанник. Персонажи могут говорить с каждым по-своему, а в текст подставляется имя пилота.
- **Шесть оформлений по корпорациям Lancer**, у каждого пилота своё:
  - **GMS** — армейский стандарт, графит и красный;
  - **IPS-N** — морская навигация, синий;
  - **КТБ** — Карракинские баронства: позолота, ливреи Домов;
  - **HORUS** — краденый узел повстанцев: помехи, изолента, на каждой загрузке свои повреждения корпуса;
  - **Smith-Shimano Corpro** — штучная роскошь, чёрный лак и янтарь;
  - **Harrison Armory** — имперский монумент, тяжёлая броня и пурпур.
- **Удобства.** Фоновая музыка своей темы и масштаб интерфейса под свой экран. Заставку запуска можно отключить.

## Что может мастер

- **Панель:** статистика выборов, список игроков и их пилоты, музыка для каждой темы.
- **Студия:**
  - диалоги собираются деревом: реплики, ветки, варианты ответа, влияние на отношения с персонажами;
  - у реплики может быть своя версия для Кавалера и для изгнанника;
  - кнопка «Авто» подгоняет скорость печати под файл озвучки, а «Проверить» тут же показывает результат;
  - каталог персонажей с портретами: видно, как портрет ляжет в рамку в каждой теме.

## Установка

Система состоит из двух частей:

- **сайт** (папка `client side`) — то, что открывают игроки в браузере;
- **сервер** (папка `server side`) — хранит аккаунты, диалоги, картинки и звук.

Сайт ищет сервер **по тому же адресу, на порту 3000**. Если сайт открывается как `https://example.com`, сервер должен отвечать на `https://example.com:3000`.

### Что понадобится

- [Node.js](https://nodejs.org/) версии 20 или новее.
- Любой веб-сервер для сайта: Apache, nginx, XAMPP и т. п.
- Домен и SSL-сертификат (проще всего бесплатный через certbot). Без сертификата сервер в обычном режиме не запустится: так безопаснее для паролей игроков.

### Шаги

1. **Сайт.** Скопируйте содержимое `client side` в папку своего веб-сервера. Настраивать в нём ничего не нужно.
2. **Сервер.** Скопируйте содержимое `server side` в любое место на той же машине. Откройте там консоль и выполните:
   ```
   npm install
   ```
3. **Настройки сервера.** Скопируйте файл `.env.example` в `.env` (рядом же) и откройте его в блокноте:
   - `CORS_ORIGINS` — адрес вашего сайта, например `https://example.com`;
   - `SESSION_SECRET` и `SETUP_KEY` — два длинных случайных пароля. Придумайте сами или сгенерируйте командой:
     ```
     node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
     ```

   Пока там стоят заготовки вроде `REPLACEME`, сервер не запустится — это нарочно.
4. **Сертификат.** Положите в папку `ssl` сервера файлы из certbot: `privkey.pem` и **`fullchain.pem`**. Именно `fullchain.pem`, а не только `cert.pem`: в нём есть промежуточный сертификат, без которого на части устройств (часто Android) браузер пишет `ERR_CERT_AUTHORITY_INVALID`. Сервер сам найдёт `fullchain.pem` (или `chain.pem`) рядом и при запуске напишет в консоли, всё ли в порядке и сколько дней осталось до конца срока.
5. **Запуск.** На Windows запустите `start.bat`, на других системах — `npm start`. Когда в консоли появится «СЕРВЕР ЗАПУЩЕН И РАБОТАЕТ», всё готово.

**Продление сертификата.** Let's Encrypt выдаёт сертификат на 90 дней, certbot продлевает его у себя в папке. Скопируйте свежие `privkey.pem` и `fullchain.pem` в папку `ssl` сервера — он подхватит их сам, перезапускать не нужно. За две недели до конца срока сервер начнёт напоминать об этом в консоли.

### Как стать администратором

1. Откройте сайт (`login.html`) и зарегистрируйтесь — **первым** пользователем.
2. Выполните в консоли команду, подставив свой домен и `SETUP_KEY` из `.env`:
   ```
   curl -X POST https://ваш-домен:3000/api/setup/first-admin -H "Content-Type: application/json" -H "Origin: https://ваш-домен" -d "{\"setupKey\":\"ВАШ_SETUP_KEY\"}"
   ```
3. Готово: первый зарегистрированный пользователь стал администратором. Повторно команда не сработает — назначить второго «первого администратора» нельзя.

## Как пользоваться

- **Игрокам** дайте ссылку на `login.html`. Они регистрируются, после заставки попадают в терминал, а в досье создают пилота.
- **Мастер** после входа видит в терминале кнопку перехода в панель (`admin.html`). Оттуда открывается студия (`studio.html`) для работы с диалогами.

## Для тех, кто настраивает сервер

<details>
<summary>Все настройки <code>.env</code></summary>

| Параметр | Что это |
|---|---|
| `PORT` | порт сервера, по умолчанию `3000` (сайт ждёт именно его) |
| `SESSION_SECRET` | секрет для входа игроков, не короче 32 символов |
| `SETUP_KEY` | ключ назначения первого администратора, не короче 16 символов |
| `CORS_ORIGINS` | адреса сайта через запятую: `https://example.com,https://www.example.com` |
| `DB_PATH` | где лежит база, по умолчанию `./database.db` |
| `SSL_KEY_PATH`, `SSL_CERT_PATH` | пути к ключу и сертификату; `fullchain.pem` или `chain.pem` из той же папки подхватываются сами |
| `ALLOW_HTTP` | `1` — запуск без SSL, **только** для проверки на своём компьютере |
| `SESSION_MAX_AGE` | сколько живёт вход, в миллисекундах (по умолчанию сутки) |

Файл `.env` не должен попадать в git: в нём ваши секреты.

</details>

<details>
<summary>Как устроена защита</summary>

- Заголовки безопасности (Helmet): CSP, HSTS при HTTPS, запрет встраивания в чужие страницы.
- Ограничение частоты запросов: общее на API и строгое на вход, регистрацию и назначение администратора.
- Защита от подделки запросов (CSRF): куки SameSite=lax и проверка адреса, с которого пришёл запрос.
- Пароли хранятся в виде хэша bcrypt; пароль — не короче 8 символов, с буквами и цифрами.
- Загружаемые файлы проверяются по расширению, типу и содержимому; пути к файлам нельзя подменить.

</details>

<details>
<summary>База данных</summary>

Обычный файл SQLite (`database.db`) без пароля: его можно открыть любой программой для SQLite (например, Navicat или DB Browser for SQLite). Перед ручными правками сделайте копию. Обновления сервера сами добавляют в базу новые поля при запуске.

</details>
