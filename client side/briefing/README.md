# Брифинги миссий: плеер и режим сценариста

Голографический брифинг на three.js — часть системы. Игрок открывает брифинги на терминале кнопкой «ЗАПИСЬ», мастер собирает их в студии (вкладка «Брифинги»). Сборка не нужна; three.js лежит в `vendor/three` (r160, лицензия MIT), из интернета грузятся только шрифты.

Модуль работает в двух режимах:
- **с сервером системы** — `editor.html?id=<id>` и `player.html?id=<id>`: сценарий хранится на сервере, звук загружается туда же, персонажи берутся из каталога студии;
- **офлайн** — без `id`: сценарий в localStorage, звук в IndexedDB, открывается хоть с диска. Удобно для черновиков и проверки без сервера.

| Файл | Что это |
|---|---|
| `player.html` | Плеер брифинга. Без параметров показывает встроенное демо «Кассиопея» |
| `editor.html` | Режим сценариста: рельеф, объекты, патрули, реплики, камера, озвучка, персонажи, планета, контракт, звук |
| `remote.js` | Связь с сервером системы: адреса API и файлов из `scripts/config.js`, загрузка звука |
| `themes.js`, `themes.css` | Темы брифинга под корпорации терминала: цвета сцены и планеты, надписи, оформление |
| `core.js` | Общее ядро: рельеф и его модификаторы, каталог моделей, сборка сцены, маркеры, портреты, хранилище озвучки |
| `voice.js` | Анализ озвучки и скорость печати. Правила перенесены из студии (`client side/scripts/voice-analysis.js`, `typing-text.js`) |
| `planet.js` | Генератор планет (имя, класс, описание, характеристики) и голографическая сфера для вступления |
| `briefing.css` | Общие цвета и стиль меток над объектами |

## Как пользоваться редактором

1. **Рельеф.** Выберите тип местности: равнины, холмы, скалы, каньон, равнины со скалами, дюны, кратеры или пустая карта. Зерно даёт другой вариант той же местности, ползунок меняет высоту. Дальше можно править кистями: поднять, опустить, сгладить, выровнять, шероховатость. Кнопки «＋ Река» и «＋ Сухое русло» прокладывают случайное русло через всю карту.
2. **Объекты.** Кликните карточку в каталоге, затем точку на карте. Shift+клик ставит несколько подряд. Ромб на карте можно тащить мышью. Q и E поворачивают объект, Del удаляет. Здания сами подгоняют землю под основание с плавным склоном вокруг. Отключается это галочкой «Подгонять землю».
3. **Рельеф-объекты** (категория «Рельеф»): кратер (радиус, глубина, вал, неровность края), шахта или скважина (узкий глубокий ствол с бортиком), холм, плато с террасами, озеро, река, сухое русло. Это модификаторы: их можно двигать и менять, земля пересчитывается сразу. Тип местности «Кратеры» ставит кратеры такими же объектами.
4. **Настройки объекта** в правой панели: сторона, шаг появления и шаг отметки, параметры типа (радиус огня, численность отряда 1–10, вейпоинты, цвет силового поля и т. д.).
5. **Шаги брифинга** внизу: текст, говорящий, пауза, озвучка, камера. У выбранного шага на карте жёлтым показаны камера и центр кадра, справа вверху — превью кадра. Значок камеры можно тащить: так меняются азимут и дистанция, а с Shift — наклон.
6. **Озвучка шага.** Загрузите файл, и «Авто» сразу найдёт начало, конец и паузы речи: печать идёт в такт голосу, каждая фраза своей скоростью, как в студии. «Проверить» печатает реплику вместе с записью.
7. **Миссия:** название, заказчик, эмблема, персонажи с портретами, планета для вступления, условия контракта. С сервером у персонажа есть кнопка «Из каталога»: картинка и кадр берутся у персонажа студии. «Кадр» открывает настройку под окно брифинга: перетаскивание двигает картинку, колесо и ползунок меняют масштаб, есть отражение и «Как в каталоге». Своя настройка относится только к этому брифингу, каталог не меняется.
8. **Звук:** своя музыка и замена стандартных звуков, подробнее ниже.
9. **▶ Просмотр** проигрывает брифинг в том же плеере. «С этого шага» в инспекторе шага начинает просмотр с выбранного места.

**Сохранение с сервером.** Правки уходят на сервер сами через пару секунд, состояние видно в шапке («сохранено на сервере ✓»). Файлы озвучки, звуков и музыки загружаются на сервер сразу при выборе. Если связь пропала, черновик остаётся в браузере, и при следующем открытии его предложат восстановить. Если брифинг тем временем сохранили из другого окна, редактор спросит, чья версия остаётся. «Плеер ↗» открывает брифинг с сервера, «← Студия» возвращает в студию.

**Офлайн.** Сценарий сохраняется в браузере: текст в localStorage, файлы в IndexedDB. «Плеер ↗» открывает `player.html?src=local`.

В обоих режимах «Экспорт» скачивает один JSON-файл со вшитым звуком, «Импорт» загружает такой файл обратно. С сервером вшитые файлы при импорте загружаются на сервер.

Управление вьюпортом: ПКМ или Alt+ЛКМ вращают камеру, СКМ сдвигает, колесо приближает, F наводит камеру на выбранный объект. Ctrl+Z и Ctrl+Shift+Z отменяют и повторяют действие.

## Плеер

Вступление: заставка заказчика, затем планета (орбита → поворот к точке → полушарие → приближение к району) и переход на карту. Справка о планете печатается, как вывод терминала: строки набираются по очереди, имя и значения характеристик «расшифровываются» из шума. Первый кадр длится, пока справка не допечатается, плюс полторы секунды, чтобы её дочитать. Пробел пропускает планету. Слева от субтитров — окно связи с портретом говорящего. При смене говорящего окно даёт помеху, в конце брифинга схлопывается.

На финальном экране — условия контракта и две кнопки: «Повтор» и «Выйти». Если игрок дошёл до финального экрана с последнего шага (а не пропустил брифинг клавишей Esc), плеер отмечает брифинг на сервере как прослушанный.

- `player.html?id=12`: брифинг с сервера для игрока (только опубликованный и доступный ему). Терминал открывает его во фрейме поверх себя; «Выйти» и «← Вернуться на терминал» закрывают фрейм.
- `player.html?id=12&studio=1`: просмотр из студии и редактора, в том числе черновика; отметку «прослушан» не ставит.
- `player.html`: встроенное демо.
- `player.html?src=local`: сценарий из офлайн-редактора (тот же браузер).
- `player.html?src=scenario.json`: файл сценария. Работает только через http-сервер, например `python -m http.server`.
- `player.html?embed=1`: просмотр в редакторе. Сценарий и файлы приходят через `postMessage`.

Плеер сообщает окну-хозяину о событиях через `postMessage`: `briefing:listened` (дослушан) и `briefing:exit` (нажали «Выйти»).

## Темы

Брифинг оформляется под ту же корпорацию, что выбрана у пилота в терминале. Терминал передаёт тему плееру (`player.html?id=12&theme=green`), плеер ставит на `<body>` класс `th-<id>`.

- `themes.js` — то, что не достаёт CSS: палитра 3D-сцены и планеты (`Core.setPalette`, `Planet.create(pl, palette)`) и надписи под лор: экран старта, лог заставки, карточка заказчика, подписи окна связи, условий и финала, шильдик с девизом.
- `themes.css` — шрифты (из `client side/assets/fonts`) и оформление каждой темы.

| Тема | Облик |
|---|---|
| GMS (`green`) | Армейская спецификация: графит, красный #DB1A2D, моноширинный шрифт, полоса спецификации, регистрационные метки, сетка чертежа |
| IPS-N (`yellow`) | Конвойная навигация: морской синий, сигнальный янтарь, корпусные плиты с заклёпками и срезанным углом, круги сонара |
| КТБ (`ktb`) | Кавалер в Доме — «Сенешаль»: бордо и позолота, капитель с засечками, гравированные таблички, герб Дома в цвете ливреи. Лансер и изгнанник — «Пурсивант»: олово и сланец, линованный реестр; у изгнанника герб перечёркнут |
| HORUS (`horus`) | Краденый узел: фосфор и глитч-маджента, пунктир, подписи в [скобках], изолента с заметками от руки, редкие рывки картинки |
| SSC (`ssc`) | LUX-Iconic: чёрный лак, янтарная волосяная линия, Jost с разрядкой, крыло бабочки, римские цифры, раскрытие от оси |
| HA (`ha`) | Монумент Ведения: пурпур, тяжёлые плиты со срезанными углами, шевроны, плашки, лучи имперского плаката, Oswald |

Положение пилота в КТБ (Дом, изгнанник, Лансер) плеер берёт из ливреи, которую терминал сохраняет в браузере (`scripts/ktb-houses.js`). Без темы — просмотр в студии и редакторе, офлайн-демо — брифинг монохромный.

## Формат сценария (JSON)

```jsonc
{
  "version": 1,
  "meta":     { "code", "title", "client", "clientNote", "emblem", "sector", "speakerId" },
  "cast":     [{ "id", "name", "role", "portrait",                // portrait — свой портрет, data URL 240×300 (офлайн)
                 "characterId", "image",                          // персонаж каталога студии и его картинка
                 "frame": { "inherit", "scale", "xRel", "yRel", "mirror" } }],   // кадр; inherit — как в каталоге
  "terrain":  { "biome", "seed", "relief", "data" },             // data — БАЗОВАЯ карта высот 161×161, Int16 ×100 в base64
  "objects":  [{ "id", "type", "name", "tag", "side", "x", "z", "rot", "scale", "ground",
                 "show", "mark", "label", "meta", /* параметры типа: range, arc, radius, depth, width, count, speed, loop, wp, pts, color… */ }],
  "steps":    [{ "id", "ch", "speakerId", "speaker", "text", "hold", "focus",
                 "cam":   { "mode": "point|object|follow", "target", "x", "z", "dist", "pitch", "yaw" },
                 "voice": { "id", "name", "duration", "start", "end", "segments", "peaks", "speed", "phraseProfile" } }],
                 // id файла: путь на сервере /assets/sounds/briefing/… или id в IndexedDB (офлайн)
  "planet":   { "show", "name", "designation", "type", "seed", "lat", "lon", "region", "desc", "stats": [[k, v]] },
  "sound":    { "sfxVol", "musicVol", "duck",
                "sfx":   { "<звук>": { "mode": "def|file|off", "id", "name", "vol" } },   // click, blip, open, out, cut, ping, hot, sweep, drone
                "music": { "intro|brief": { "id", "name", "vol", "loop" } | null } },
  "contract": { "title", "rows": [[k, v]], "objectives": [{ "text", "main" }], "rewards": [[k, v]] },
  "assets":   { "audio": { "<id файла>": "data:audio/…" } }      // озвучка, звуки и музыка; только в экспортированном файле
}
```

Итоговый рельеф собирается так: база, затем модификаторы рельеф-объектов, затем площадки под зданиями. Поэтому в файле хранится только база, а кратеры, реки и площадки пересчитываются из объектов.

`show` и `mark` ссылаются на `id` шага. Кроме того, допустимы значения `"start"` (сразу) и `"never"` (только для `mark`). Поэтому при перестановке шагов привязки не ломаются.

## Планеты

Поверхность планеты строится по алгоритмам генератора PixelPlanets: острова, землеподобная с реками, сухая, ледяная с озёрами, безатмосферная с кратерами, лавовая. Пиксели, дизеринг и палитры оригинала не используются: планета монохромная, с контурами берегов, рек, озёр и кратеров, облака — отдельный слой со штриховкой. Шум считается в 3D на сфере. В редакторе у планеты есть тип, зерно, облачность, наклон оси, направление света (откуда и насколько сбоку) и точка района. Лицензия оригинала — в `THIRD_PARTY_LICENSES.md`.

## Отряд «Дикие»

Отряд из 1–10 особей на выбор: мех, человек, шар или куб. Геометрия время от времени сбоит, как от сильных помех: её растягивает, сдвигает и двоит. Частоту и силу сбоев задаёт ползунок «Сила помех».

## Звук и музыка

Вкладка «Звук» в редакторе.

- **Музыка.** Две дорожки: «Вступление» (заставка заказчика и планета) и «Брифинг» (карта и реплики). На карте музыка брифинга плавно сменяет музыку вступления. Если музыки брифинга нет, дальше играет музыка вступления. У каждой дорожки своя громкость и флажок «По кругу».
- **Звуки.** Нажатие, печать, появление и угасание логотипа, склейка кадров планеты, отметка, тревога, развёртка карты, фоновый гул. Каждый можно оставить стандартным (он синтезируется в браузере), заменить своим файлом с отдельной громкостью или выключить. Кнопка ▶ проигрывает текущий выбор. Если свой файл не нашёлся, играет стандартный звук.
- **Громкость.** Общие ползунки для звуков и музыки. Флажок «Приглушать музыку, пока звучит озвучка» убавляет музыку под голос реплик. Сама озвучка от этих ползунков не зависит.

Клавиша M в плеере выключает весь звук, включая музыку.

## Хранение на сервере

Таблица `briefings`: сценарий целиком лежит JSON-документом в колонке `scenario`, рядом колонки для отбора — название, код, заказчик, доступ (`allowed_users`, как у диалогов), публикация, порядок, версия. Сценарий читается и пишется только целиком, а его структура часто меняется, поэтому раскладывать его по таблицам незачем: старые сценарии дополняет `normalize()`. Файлы звука лежат в `server side/assets/sounds/briefing/`, в сценарии только пути. Прошлые версии сценария хранятся в `briefing_revisions` (не чаще раза в 10 минут, последние 30). Отметки «прослушан» — в `briefing_views`.

API — `server side/routes/briefings.js`: для игрока `/api/briefings` (список, сценарий, отметка), для студии `/api/editor/briefings` (создание, сохранение с проверкой версии, публикация и доступ, копия, удаление, прослушавшие, ревизии, загрузка звука). Сервер проверяет сценарий: ссылки на файлы — только в свои папки `assets`.

Портрет персонажа из каталога сервер подставляет в сценарий сам, когда отдаёт его игроку: у игрока нет доступа к API каталога. Кадр — по той же формуле, что рамка терминала (`scripts/portrait-frame.js`): окно связи почти той же пропорции, что рамка 258×319, поэтому кадр из каталога ложится без пересчёта.
